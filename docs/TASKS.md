# TASKS

작업 현황, 담당자, 우선순위를 관리한다. 상태 값은 `대기`, `진행 중`, `검토 중`, `완료`, `보류` 중 하나를 쓴다. 구현 작업은 QA·성능 엔지니어의 검증을 통과해야 `완료`로 바꾼다.

## 목표

대량의 병사가 3D 지형 위에서 싸우는 실시간 전략 게임을 TypeScript + three.js로 만든다. 레퍼런스는 Heroes Battlefield Demo(itch.io)이며, 분석만 하고 구현과 리소스는 직접 만든다(D-002).

## 진행 순서

1단계에서 레퍼런스를 분석하고 프로젝트 뼈대를 만든다. 2단계에서 분석 결과를 바탕으로 기획과 아트 방향을 정한다. 3단계에서 기능을 구현하고, 4단계에서 검증한다.

```
1단계: 레퍼런스 분석 + 프로젝트 뼈대 → 2단계: GDD + 아트 스타일 + 리소스 → 3단계: 구현 → 4단계: QA 검증
```

## 병렬 작업 파일 범위 (1단계, 종료)

1단계에서는 세 팀원이 동시에 일하므로, 파일이 겹치지 않게 범위를 나눈다. 아트 디렉터는 스타일 가이드를 먼저 쓰고, 모델 제작은 `docs/ARCHITECTURE.md`의 리소스 규격이 나온 뒤 시작한다.

- 리버스 엔지니어: `docs/REFERENCE_ANALYSIS.md`, `docs/reference/` 만 쓴다.
- 테크니컬 아키텍트: `package.json`, 잠금 파일, `tsconfig*.json`, `vite.config.*`, `index.html`, `.gitignore`, `src/`, `public/`, `docs/ARCHITECTURE.md` 만 쓴다.
- 게임 디자이너: `docs/GDD.md`, `docs/BALANCE.md`, `tools/balance/` (T-015에서 `src/`는 읽기와 실행만)
- QA·성능 엔지니어 (T-011): `docs/QA.md`, `tools/qa/`, `tests/e2e/`(만들 경우). `src/`는 고치지 않고 버그로 기록한다. 만 쓴다.
- 아트 디렉터: `docs/ART_STYLE_GUIDE.md`, `public/assets/`, `tools/art/` 만 쓴다. T-005는 병종 4종의 메시·골격·스킨과 지형 텍스처·소품까지이고, 애니메이션 클립은 T-009가 만든다.
- 애니메이션·VFX 스페셜리스트: `tools/anim/`, `docs/ANIMATION_GUIDE.md`, 테크니컬 아키텍트와 합의한 `public/assets/units/` 하위 클립 출력 파일만 쓴다. 아트 디렉터의 파일은 덮어쓰지 않는다.
- 게임 디렉터: `docs/TASKS.md`, `docs/DECISIONS.md` 만 쓴다.
