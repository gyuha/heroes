# Animation Guide

T-009a / 2026-10-23. ARCHITECTURE §5.2·§7.5, ART_STYLE_GUIDE, DECISIONS D-001~D-010, GDD §4.5·§5.4·§5.5 및 REFERENCE_ANALYSIS §9를 기준으로 한다.

## 납품 구조와 승인

게임 디렉터가 이 작업 대화에서 별도 파일 계약을 승인했고 아키텍처 반영은 디렉터가 아키텍트에게 중계한다. 이 세션은 Paseo의 봇 간 재요청 제한으로 ask_bot이 없어 아키텍트와 직접 합의하지 않았다.

- 원본: `public/assets/units/{infantry,spearman,archer,cavalry}/{병종}.glb`. 읽기만 한다.
- 출력: 같은 디렉터리의 `animations.glb`. 메시·스킨·머티리얼·이미지 없이 원본 노드 이름·인덱스·계층·바인드 TRS와 장면을 보존한다. 원본의 메시 운반 노드는 빈 노드로 남긴다. `skins`가 없는 것은 의도적이며 원본 모델의 스킨을 사용한다.
- 생성 도구: `tools/anim/`. 아트의 `generate.py`는 자신의 `{병종}.glb`만 쓰므로 별도 파일은 삭제되지 않는다. 아트 골격이나 스킨이 바뀌면 애니메이션 도구를 다시 실행한다. 이전 골격에 맞춘 파일을 무조건 재사용하지 않는다.
- T-007 연동: 두 GLB를 로드하고 **원본 모델의 scene**에 AnimationMixer를 만든 뒤 별도 파일의 `animations`를 연결한다. 애니메이션 파일의 빈 scene을 그리거나 골격으로 대체하지 않는다. 노드 이름은 병사별 별도 scene 내부에서 바인딩한다.

## D-015: 해부학적 좌우와 레거시 본 접미사

**정면은 +Z이며 -X가 해부학적 오른쪽, +X가 해부학적 왼쪽이다. 현재 골격은 접미사가 반대여서 `_l`이 오른팔/오른손(-X), `_r`이 왼팔/왼손(+X)이다.** 이 이름을 고치거나 바인드를 바꾸지 않는다. 여기의 ±X는 +Z 정면인 캐릭터 로컬 좌표 기준이며, 게임 heading을 적용한 월드 좌표의 부호를 뜻하지 않는다.

아트의 D-015 확정 모델은 검·창을 `hand_l`에, 방패·활을 `hand_r`에 웨이트한다. 궁수는 활을 왼손(+X, hand_r)으로 받치고 오른손(-X, forearm_l/hand_l)으로 시위를 당긴다. 궁수가 활까지 오른손에 들어야 한다는 뜻은 아니다.

- attack: upper_arm/forearm/hand의 `_l`↔`_r` 대상 교환. X면 반사에서 Euler `(x,y,z) → (x,-y,-z)`, quaternion `(qx,qy,qz,qw) → (qx,-qy,-qz,qw)`. 공격 상체·머리의 Y/Z 회전도 반사해 찌르기·조준 방향을 맞춘다.
- die: 무기 팔만 바꾸면 새 오른손의 긴 창이 지면을 향한다. 인체·말 전체를 X면 반사하여 쓰러짐 방향을 바꾸고, 인간 좌우 본 및 말 다리 0↔1·2↔3을 교환한다. hips 이동의 X 부호도 반전하며 루트는 계속 고정한다. 큰 수직 보정으로 1m 이상 띄우는 방식은 쓰지 않는다.
- idle/hit는 무기 팔에 특화된 비대칭 트랙이 없어서 유지한다. walk/run의 보행병 팔은 다리와 반대 위상인 대칭 보행이므로 대상 교환하지 않는다. 기병 이동의 양팔 자세도 대칭이다. 기병 보폭·보행 주기와 speed는 유지한다.
- fps/intervals/loop/speed/hitTime와 클립 이름·길이·샘플 수는 변경 전과 정확히 같다. `t014b_baseline.json`은 수정 시작 시 확정된 아트 노드·해시와 기존 메타데이터를 기록한다.

최종 결합 검사는 실제 GLTFLoader/AnimationMixer로 수행한다. `node tools/anim/verify_handedness.mjs`는 아트 해시·본/바인드 노드 불변, 장비의 손 웨이트/좌표, 공격 이벤트 시점 오른팔 움직임, 메타데이터·샘플 보존, die 전 31샘플의 장비 최저 높이를 검증한다. Node 로더가 추가하는 isBone 표식만 노드 비교에서 제외한다. `verify.mjs --grounded`는 모든 클립의 모든 정점에 대해 별도로 검사한다.

| 병종 | 공격 이벤트 | 오른 상완(-X, upper_arm_l) 회전량 | die 장비 최저 Y (m) |
|---|---:|---:|---:|
| 보병 | f12 | 90.63° | 검 0.75034 / 방패 −4.58e−8 |
| 창병 | f12 | 73.00° | 창 0.10000 / 방패 0.07935 |
| 궁수 | f16 | 75.44° | 활 −5.64e−8 (오른 전완 당김도 별도 확인) |

수치의 음수는 허용 오차 1e−6m 이내다. 공유 보행병 die의 수직 보정 상한은 0.44033m(활·인체 포함 공통 최저점 기준), 기병 die는 0m다. 장비가 바닥 아래로 내려가던 방향을 바로잡았으며 사망 자세는 마지막 프레임에서 유지한다.

- `handedness.json`: 결합 검사 수치 및 이벤트 전후 본/장비 위치

- 사망 시트 재생성: `blender -b --python tools/anim/preview.py -- --death-sheet`

## 기본 클립과 이벤트

모든 병종이 다음 길이·이름을 사용한다. 프레임은 **0 기반**이며 종료 프레임을 포함한 샘플 수와 시간 구간 수를 구분한다.

| 클립 | 초 | 구간 수 | 샘플 수 | 반복 | 시각 이벤트 프레임 |
|---|---:|---:|---:|---|---|
| idle | 1.2 | 36 | 37 | 예 | 없음 |
| walk | 1.0 | 30 | 31 | 예 | 보행병 좌/우 접지 기준 0/15, 말은 발별 위상 사용 |
| run | 0.8 | 24 | 25 | 예 | 보행병 좌/우 접지 기준 0/12, 말은 비대칭 질주 위상 |
| attack | 0.8 | 24 | 25 | 아니오 | 보병·창병·기병 접촉 강조 12(0.4초), 궁수 방출 16(0.533초) |
| hit | 0.3 | 9 | 10 | 아니오 | 반동 최대 2(약 0.067초) |
| die | 1.0 | 30 | 31 | 아니오 | 쓰러짐 정착 23(약 0.767초), 마지막 자세 유지 |
| **합계** | **5.1** | **153** | **159** | | 6초 예산 이내 |

이벤트는 이 문서의 연동 계약이며 glTF 애니메이션 이벤트 트랙이 아니다. 명중·피해·발사는 시뮬레이션 틱이 권위자다. 현재 틱에서 결정된 결과를 애니메이션이 끝날 때까지 지연하지 않는다. 공격 예비 구간에 취소되면 해당 공격 토큰의 미발생 연출 이벤트를 제거한다. 이미 확정된 피해·발사는 취소하거나 중복 실행하지 않는다. 궁수의 4초 발사 간격(GDD §5.5)은 0.8초 클립을 늘려서 표현하지 않고 쿨다운 상태에서 idle을 사용한다.

## 재생 메타데이터 (계약 수정 반영)

각 glTF 애니메이션의 `extras`에 기존 fps/intervals/loop를 유지하고 다음 값을 저장한다. 최종 수치는 `validation.json` 및 GLTFLoader의 `parser.json.animations[].extras`에서도 확인한다. three.js의 AnimationClip 사용자 필드로 자동 복사된다고 가정하지 않는다.

| 병종 | walk.speed (m/s) | run.speed (m/s) | attack.hitTime (초) |
|---|---:|---:|---:|
| infantry | 1.809891 | 3.931617 | 0.4 |
| spearman | 1.809891 | 3.931617 | 0.4 |
| archer | 1.809891 | 3.931617 | 0.5333333333333333 |
| cavalry | 3.600272 | 7.175335 | 0.4 |

speed는 원본 메시의 발/말 다리 본에 귀속된 밑면 정점들을 실제 스키닝한 뒤, 발 높이가 낮은 1/3 구간(+1cm 허용)에서 뒤로 움직이는 구간의 평균 후방 속도를 측정한 값이다. `실제 이동 속도 / extras.speed`로 재생 배율을 정한다. 게임 밸런스상의 걷기/달리기 속도를 의미하지 않는다. 현재 사인 기반 보행의 순간 접지 속도는 일정하지 않으므로 이 값은 평균 미끄러짐을 줄이는 기준이며 완전한 발 고정을 보장하지 않는다. 측정 RMS 편차는 보행병 walk 0.6144 / run 1.1990m/s, 기병 walk 0.9143 / run 0.9393m/s다. 엄밀한 무미끄러짐은 일정 접지 궤적 또는 발 고정 IK의 후속 작업이 필요하다.

hitTime은 근접 f12/30, 궁수 방출 f16/30이다. 다음 타격 시각에서 hitTime을 빼 클립 시작 시각을 정하고 첫 교전의 확정 타격은 hitTime 위치부터 재생한다(ARCHITECTURE §11.5). 원래 fps·intervals·loop 메타데이터도 유지한다. 검사기는 값의 존재·유효성·이벤트 프레임 일치를 검증하며, 모든 translation 대상이 hips인지, root 회전/이동 채널이 아예 없는지도 검사한다.

### 기병 게임 속도 대응 (디렉터 수정 요청 반영)

| 상태 | 사용 클립 | 게임 속도 | 측정 speed | 재생 배속 |
|---|---|---:|---:|---:|
| 속보 이동 | walk | 3.5m/s | 3.600272m/s | ×0.97215 |
| 구보·습보 이동 | run | 7.0m/s | 7.175335m/s | ×0.97556 |
| 최고 속도 돌격 | run | 9.0m/s | 7.175335m/s | ×1.25430 |

세 배속 모두 목표 0.8~1.3 안이다. calibrate.py와 validate.py가 이 범위를 검사한다. 돌격 전용 클립은 추가하지 않았다. `cavalry_revision.json`은 배속 계산과 변경 전후 보행병 3종의 GLB SHA-256 불변을 기록한다. 기병 속도 조정 당시의 수정은 기병 walk/run에 한정했으며 보행병 3종 파일을 다시 쓰지 않았다. 이후 D-015의 별도 좌우 교정에서는 4병종 attack/die를 재생성했다.

## 동작 원칙

공유 골격 보행병 3종은 attack을 제외한 5클립의 모든 본 트랙이 수치상 동일하다. 파일은 병종별로 제공하지만 런타임은 동일 트랙·베이크 데이터를 공유할 수 있다. attack은 검 베기, 창을 수평으로 낮춰 내미는 찌르기, 왼팔로 활을 받치고 오른손을 당긴 뒤 놓는 사격으로 구분한다. 궁수 활은 손목 보정으로 조준 중 세로 실루엣을 유지한다. 활시위 변형·화살 장전·발사체는 포함하지 않는다. 기존 단일 메시·본 구조를 유지하기 위해 별도 활시위 본을 추가하지 않았다.

기병은 말 4다리의 위상, 말 몸통·머리와 기수 상체의 후속 움직임을 함께 사용한다. 기병 walk는 대각선 다리쌍을 교대로 내미는 속보(1초 클립 안에 2주기, 주기당 0.5초·다리 전후 진폭 31°), run은 앞·뒷다리 위상이 다른 구보·습보(0.8초 클립 안에 2주기, 주기당 0.4초·전후 진폭 46°)다. 게임 속도에 맞추기 위해 보폭과 클립 내부 주기를 조정했으며 extras만 부풀리지 않았다. 말 다리당 본 1개인 원본 23본 구조이므로 무릎·발목의 독립 굴곡은 없다. 기수는 말에 걸터앉은 자세를 기본으로 유지한다. 사망은 말과 기수가 함께 옆으로 쓰러진다(D-015 이후에는 X 반사한 방향).

루트 본과 리그 오브젝트는 고정한다. 이동 채널은 hips 1개만 허용하며 root는 고정값 채널도 내보내지 않는다. chest·horse_body 이동은 제거하고 상체 기울기·말의 회전과 다리 회전으로 대체했다. 기병은 몸통 수직 이동 대신 다리 벌림과 넘어질 때의 접기 동작으로 지면 관통을 피한다. 보행은 사인 위상, 예비 동작·반동·복귀는 smoothstep으로 샘플링하고 glTF에서는 LINEAR로 보간한다. 스케일 키·모프·루트 모션·파티클·화면 흔들림은 없다. 전 병사가 공격할 때 화면 전체 플래시나 hit stop을 넣지 않는다.

실제 원본 메시의 스키닝 정점으로 지면 최저점을 구하고 hips의 수직 오프셋만 보정한다. 말 몸통의 translation은 사용하지 않으며 회전으로만 움직인다. 공유 클립은 보행병 3종의 공통 최저점을 사용해 트랙 공유를 보존한다. 원점과 지형 이동은 바뀌지 않는다. 평지 정점 관통은 부동소수점 오차 범위까지 검사하며 경사 적응 IK는 제공하지 않는다. 최종 검사 최저 정점은 −5.64×10⁻⁸m로, 허용 오차 10⁻⁶m 이내다.

## 전환·취소·중첩 규칙 (T-007 구현 계약)

우선순위는 die > 명중 결과의 시각 반동 > attack > 이동 > idle. 사망은 언제든 즉시 전환하고 이후 상태 이벤트를 무시한다. die는 LoopOnce + clampWhenFinished로 마지막 자세를 유지한다. 살아 있는 유닛으로 재사용할 때 action·타이머·미발생 이벤트·포즈를 모두 초기화한다.

이동/대기 간 블렌드는 0.08~0.12초, 공격 진입 0.05초, 공격/피격 복귀 0.08초를 권장한다. 입력·이동 명령·회전·피해 계산은 즉시 적용한다. 피격 연타는 매번 이전 반동 위에 더하지 않고 단일 hit를 갱신하며, 실제 공격 판정을 피격 클립이 지연하지 않는다. GPU 베이크 플레이어가 클립 간 블렌딩을 지원하지 않으면 즉시 교체해도 된다. 블렌딩 구현과 상태 취소 보장은 T-007에서 확인해야 한다.

반복 베이크는 마지막 중복 자세를 별도 구간으로 재생하지 않는다. 구간은 walk 30, run 24, idle 36개다. 비반복은 종료 샘플을 포함하고 clamp한다. 병사별 위상을 분산하되 사격·명중 이벤트를 임의 위상으로 옮기지 않는다. 속도에 따른 보행 배율은 시뮬레이션 실제 이동속도에 맞추며, 발 미끄러짐은 실제 게임에서 조정한다.

## 성능 예산

원본은 보행병 17본, 기병 23본이며 정점당 활성 영향 본은 최대 1개다. 159개 종료 포함 샘플 전체를 RGBA32F 본 행렬로 저장하면 병종당 보행병 172,992바이트, 기병 234,048바이트다(패딩·추가 버퍼 제외). 4병종을 독립 저장하면 753,024바이트이며 공유 트랙 재사용으로 더 줄일 수 있다. 최종 텍스처 패킹·Half Float 선택은 렌더러 담당이다.

별도 파일에는 메시·이미지가 없으므로 자체 드로우콜은 0이다. 재생 코드에서 병사마다 SkinnedMesh/AnimationMixer를 만드는 대신 로드 시 한 번 베이크한다. 생성 GLB 4개는 합계 약 0.30MB다. 수천 명 GPU 재생·목표 기기 60fps는 T-007/T-011 통합 검증 항목이며 이번 정점 재수입 검증으로 대체하지 않는다.

## 재생성과 검증

프로젝트 루트에서 `python3 tools/anim/build.py` 실행. Python 표준 라이브러리와 프로젝트의 node/three 의존성을 쓴다. 아트 파이프라인 실행은 필요 없다. 기병만 갱신할 때는 `HEROES_ANIM_UNIT=cavalry python3 tools/anim/build.py`를 사용한다. 다른 병종 파일은 읽기·검사만 하며 재작성하지 않는다. `--preview`를 붙이면 Blender와 ffmpeg로 시트 4장과 GIF를 다시 만든다.

순서: 원본 해시 보관 → generate.py → verify.mjs(실제 GLTFLoader 재수입·바인딩·AnimationMixer·매 프레임 CPU 스키닝) → ground.py(지면 보정) → verify.mjs(보정 후 정점 재평가) → calibrate.py(접지 속도 측정·extras 기록) → validate.py(독립 바이너리 계약 검사) → verify.mjs(최종 재검사) → 원본 해시 불변 검사. 반복 빌드의 출력 4파일 SHA-256이 바이트 단위로 동일함을 확인했다. action 중단 후 원래 본 TRS로 복귀하는 검사도 통과했다. ground.py만 연속 실행해 오프셋을 중복 적용하지 말고 build.py를 사용한다.

- `generation.json`: 원본/출력 SHA-256와 파일 크기
- `validation.json`: 클립 길이·샘플·루트 이동·반복 자세 차이·본/영향 수·바인드 계층 일치
- `roundtrip.json`: 실제 로더 트랙 수·재생 샘플 수·정점 이동·최저/최고 높이
- `grounding.json`: 클립별 지면 보정량
- `locomotion.json`: 접지 구간에서 측정한 기준 속도·구간 수·순간 속도 편차
- `cavalry_revision.json`: 기병 게임 속도별 배속과 보행병 파일 해시 보존 결과
- `{병종}_sheet.png`: 각 클립의 0/25/50/75/100% 프레임(기병 walk/run은 2주기 중 첫 주기를 읽도록 0/12.5/25/37.5/100%). 그림과 라벨은 원근 투영되므로 행은 아래에서 위로 idle/walk/run/attack/hit/die다.
- `cavalry_game_speeds.gif`: 기병 3.5m/s 속보·7m/s 구보/습보·9m/s 돌격을 실제 재생 배속으로 나란히 표시한다. `blender -b --python tools/anim/preview.py -- --game-speeds`로 프레임을 재생성한다.
- `motion.gif`, `sequence/*.png`: 4병종 walk/run/attack 재생. GIF 12fps는 미리보기만 해당하며 원본은 30fps다. 각 클립 주기가 달라 GIF 전체 재시작 지점은 이어지지 않을 수 있다.

미리보기는 **원본 GLB에 별도 파일을 연결해 three.js에서 평가한 실제 스키닝 정점**을 Blender로 렌더한다. 새 메시로 애니메이션을 흉내 낸 것이 아니다. 정점 평가에는 실제 메시·스킨을 쓰고, Node 환경의 이미지 디코더만 빈 Texture 플러그인으로 대체한다. 렌더 단계는 아트 원본 팔레트와 팀색 마스크를 사용한다. 실제 WebGL 셰이더·게임 카메라·대량 병력 가독성·애니메이션 취소·중첩은 런타임 미통합으로 미검증이다.
