# ART STYLE GUIDE

상태: T-005 2단계 1회 수정·자체 검수, 2026-10-23. ARCHITECTURE.md §7과 REFERENCE_ANALYSIS.md §11.4를 확인했다. 런타임 계약은 아키텍처 문서를 따른다. QA 최종 승인은 별도다.

## 방향: 조각된 전장

저폴리 목조 조각과 접힌 금속 판을 연상시키는 독자적인 전장 미니어처 스타일. 넓은 면, 절제된 채도, 분명한 무기 외곽선을 사용한다. 얼굴 묘사·장식 문양보다 병종과 진영 판독을 우선한다. 지형은 넓고 부드러운 높이 변화 위에 각진 암석·수관을 배치한다.

D-002에 따라 Heroes Battlefield Demo의 모델, 텍스처, 이미지, 코드와 데이터를 사용하거나 형태를 본뜨지 않는다. 본 문서의 조각 형태·팔레트·실루엣 체계는 프로젝트용 신규 방향이다. 레퍼런스 분석의 2D 픽셀 아트는 형태 제작에 사용하지 않았다. 진영색을 넓은 망토·방패 면에 배치한다는 가독성 원칙만 참고했다.

## 면과 음영

- 큰 면의 플랫 노멀을 기본으로 한다. 둥근 얼굴·작은 체인메일·가는 테두리 등 원거리 노이즈를 만들지 않는다.
- 밝은 윗면, 중간 측면, 어두운 하부의 세 단계 명도 관계를 지향한다. 실제 구현은 아키텍처 머티리얼 규격을 따른다.
- 금속은 차가운 회색과 작은 밝은 면으로 표현한다. 강한 반사, 발광 갑옷, 유닛 전체 외곽선은 사용하지 않는다.
- 무기·방패·몸통 사이에는 명확한 빈 공간을 둔다. 세부 장식으로 삼각형 예산을 소비하지 않는다.

## 진영 색과 접근성

색 값은 sRGB 아트 기준이다. 렌더러의 색 공간 변환을 거쳐 표시하며 파일에 선형값을 넣을지는 T-003 규격을 따른다.

| 역할 | 색 | 적용 |
|---|---|---|
| 청람 진영 A | #247DA8 | 넓은 몸통·방패 주면 |
| 황토 진영 B | #E4A33B | 넓은 몸통·방패 주면 |
| 공통 암부 | #28323D | 장갑 틈, 부츠, 무기 손잡이 |
| 공통 밝은 면 | #E6DCC4 | 얼굴, 소량의 금속 하이라이트 |
| 공통 금속 | #87969C | 투구·날의 넓은 면 |
| 공통 목재 | #655044 | 창대·활·안장 |
| 말 털 | #AE7D53 | 목재보다 밝은 갈색 몸체·목·다리 |

청색/황색 계열과 명도 차이를 함께 사용한다. 진영 색은 화면에 보이는 몸통·방패 면의 충분한 넓이를 차지해야 한다. A는 밝은 세로 표식, B는 어두운 가로 표식을 보조 식별 후보로 삼되, 단일 머티리얼·인스턴스 색 규격과 양립하는지 확인 후 채택한다. 표식을 지원하지 못하면 UI 진영 마커의 형태 차이로 보완하도록 UI 담당자와 조율한다. 색만으로 접근성을 충족했다고 판정하지 않는다.

필수 검수: 원본, 회색조, 적색·녹색·청색 계열 색각 시뮬레이션에서 진영을 비교한다. 선택/공격 표시는 진영 색을 덮지 않고 별도 형태로 표현한다. 회색조 RTS 미리보기는 검수했으며 색각 시뮬레이션 및 실제 게임 화면 검수는 미실시다.

## 병종 비율과 실루엣

기본 인체는 약 4등신, 큰 머리와 단단한 몸통, 짧고 굵은 팔다리를 사용한다. 키의 기준은 발바닥부터 투구 정점까지이며 무기 끝은 제외한다. 실제 월드 단위·축·원점은 T-003 확정값을 따른다.

| 병종 | 고유 실루엣 | 구분 기준 |
|---|---|---|
| 보병 | 넓고 각진 방패 + 짧은 검 | 방패가 몸통 옆의 큰 사각 덩어리로 읽힌다 |
| 창병 | 머리 위로 길게 솟는 창 + 좁은 방패 | 가장 긴 세로선, 창날과 투구 사이 여백 |
| 궁수 | 몸통 옆으로 벌어진 활 + 낮은 후드 | 활의 열린 곡선·다각형 윤곽, 큰 방패 없음 |
| 기병 | 길쭉한 말 몸통 + 높은 기수 | 네 다리와 수평 몸통, 보병보다 큰 점유 면적 |

보병·창병·궁수의 인체 비율은 동일하게 유지한다. 병종 차이는 장비 외곽선으로 만든다. 활시위와 화살통은 보조 요소이며 이것만으로 궁수를 구분하지 않는다. 말과 기수는 단일 메시·골격으로 납품한다. 골격 구조는 아래 계약대로이며, 애니메이션 클립은 T-009에서 제작한다.

지형의 게임 효과는 GDD가 결정한다. 아트만으로 통행 가능 여부를 임의 정의하지 않는다. 경사·숲 경계·물 경계는 장식과 분리해 읽히게 한다. 첫 소품 후보는 넓은 수관 나무, 침엽수, 큰 절리 바위의 3종이다. 텍스처 없이 버텍스 컬러로 구현 가능한 방향을 우선 검토하되 저장 형식은 T-003을 따른다.

## 조명·하늘·안개

따뜻한 미색 주광과 차가운 중성 환경광을 사용한다. 하늘은 저채도 회청색 #BBCBD1, 원거리 안개는 #B9C7C9를 목표로 한다. 강한 노을과 녹색 색보정은 기본 전투 조명에서 피한다. 그림자는 접지와 높이 인지에 쓰며 수천 병사 개별 실시간 그림자 여부는 렌더링 예산에 따른다. 물과 눈에서도 병사 암부가 남도록 노출을 맞춘다.

## 카메라 거리별 가독성 검수

거리의 월드 단위 대신 화면에 표시된 보행 병사 높이로 판정한다. 최종 카메라 설정 확정 후 대응 거리를 기록한다.

| 화면 높이 | 필수 판독 | 검수 방법 |
|---|---|---|
| 64px 이상 | 병종·진영·무기 형태 | 네 병종 정면/측면/실제 전투 각도 |
| 24–63px | 병종 외곽선과 진영 주면 | 흑색 실루엣, 회색조, 양 진영 나란히 |
| 12–23px | 진영과 보행/기병 구분, 부대 구성 | 실제 지형 위 밀집·산개 배치 |
| 12px 미만 | 부대 단위 진영·위치 | UI 마커/집계 표시 담당자와 확인 |

24px 이상에서 병종 식별을 목표로 하며 12px 미만의 개별 병종 식별은 보장하지 않는다. 실제 게임의 최소 운용 크기가 목표보다 작으면 과장 비율 또는 표시 체계를 재검토한다. 합격은 미리보기와 실제 화면을 보고 판정한다.

## 확정 리소스 계약 및 제작 원본

아키텍처 §7.1–7.9를 준수한다. 런타임 경로는 `public/assets/`이며 생성 스크립트·원본·검수 결과는 `tools/art/`다. 병종 ID는 `infantry`, `spearman`, `archer`, `cavalry`로 납품했다. 지형 ID는 D-009와 GDD §6.1이 확정한 0~6을 따르며, T-013에서 4번의 의미 변경과 5번 리소스를 반영했다.

### 재생성과 파일

```sh
blender --background --factory-startup --python tools/art/generate.py
python3 tools/art/validate.py
blender --background --factory-startup --python tools/art/verify_blender.py
blender --background --factory-startup --python tools/art/preview_terrain.py
blender --background --factory-startup --python tools/art/preview_rts.py
```

Blender 5.2.1 LTS로 실행했다. 외부 라이브러리 없이 생성하며, 지형 노이즈와 미리보기 배치는 고정 시드를 사용한다. 생성기는 해당 납품 모델·텍스처·원본·비교 이미지만 덮어쓴다. 실행 시 Blender 백그라운드 씬을 초기화하므로 열려 있는 GUI 씬을 대상으로 실행하지 않는다.

- `tools/art/generate.py`: 메시·골격·팔레트·표면 텍스처·소품 및 비교 이미지 생성.
- `tools/art/army_source.blend`: 편집 가능한 전체 원본, 프리뷰 배치 전 저장.
- `tools/art/unit_palette.png`: 256² RGBA 팔레트 원본. 각 유닛 GLB에도 내장된다.
- `tools/art/validate.py`, `validation.json`: 실제 GLB accessor/buffer 검사와 측정값.
- `tools/art/verify_blender.py`, `roundtrip_validation.json`: 내보낸 GLB 재수입·관절 회전·PNG 검사.
- `tools/art/preview_terrain.py`, `terrain_comparison.png`: 지형 5종 각각 3×3 반복·소품 3종 별도 미리보기.
- `tools/art/preview_rts.py`, `rts_24px.png`, `rts_12px.png`, `rts_24px_gray.png`: 실제 GLB를 재수입한 192명 밀집 배치, 각 진영 96명.
- `tools/art/rts_measurements.json`: 기준 보병 전체 투영 높이와 카메라 스케일 측정.
- `tools/art/unit_comparison.png`: 1600×1050, 4병종 × 청람/황토 진영 비교.

### 형상·골격·머티리얼

1m=1, +Y 위, +Z 정면. 보행병 투구 정점 1.87m(궁수 후드 1.84m), 기병 기수 투구 정점 2.52m, 말 포함 길이 약 2.52m. 창 등 무기를 포함한 전체 bounds는 더 크다. 피벗은 발밑 `(0,0,0)`이고 장비로 비대칭인 바운딩 박스 중심과 구분한다. GLB 씬 루트·메시 노드 변환은 단위 변환이다.

보행 3종의 17본 이름·계층·바인드 변환은 동일하다. 본은 `root`, `hips`, `spine`, `chest`, `head`, 좌우 `upper_arm`, `forearm`, `hand`, `thigh`, `shin`, `foot`에 `_l`, `_r` 접미사를 사용한다. root는 바닥 원점이다. 기병은 같은 인체 골격을 0.65m 올리고 말 몸체·머리·네 다리 6본을 더한 23본 확장이다. 기병은 보행 골격과 바인드 변환이 다르므로 보행 클립의 무수정 공유 대상이 아니다.

전 정점은 1개 본에 1.0 웨이트를 가진다. 조각 인형 방향에 맞춘 강체 파츠이며 팔·다리 관절 경계는 별도 덩어리다. 부드러운 피부 변형을 기대하는 리그가 아니다. 무기·방패·활은 손 본, 망토·화살통은 chest에 고정되어 별도 메시가 없다. 클립 6종은 T-009 담당이며 이번 파일에는 애니메이션을 넣지 않았다. 원본 리그 구조를 유지해 후속 클립을 만든다.

몸통·장비는 플랫 노멀, 팔다리는 정점 예산을 맞추는 스무스 노멀을 사용한다. 모든 모델은 메시·프리미티브·머티리얼 각각 1개다. 병사는 Base Color 팔레트만 사용하며 metallic=0, roughness=0.85, OPAQUE다. 소품은 선형 COLOR_0, 흰 Base Color, roughness=0.9, 텍스처 없음이다.

팔레트는 폭 42px의 6칸(팀, 암부, 피부, 금속, 목재, 말 털)이며 UV는 각 칸 중앙을 참조한다. 팔레트의 알파 255는 팀색 영역(RGB 200), 알파 0은 원래 색 영역이다. 팀색은 선형 공간에서 `base.rgb * mix(vec3(1), teamColor, base.a)`로 적용한다. 알파는 투명도로 연결하지 않는다. 표준 glTF 뷰어에서는 회색 팀 영역이 정상이며, 팀색 구현은 런타임 커스텀 셰이더가 필요하다. 비교 이미지는 같은 곱셈 공식을 Blender 노드로 구현했다. 이미지의 알파 0 영역 RGB를 보존하기 위해 Blender `CHANNEL_PACKED` 설정을 사용한다.

### 지형 납품

T-005 최초 납품은 `grass`, `forest`, `rock`, `sand`, `water`의 `_albedo.png` 5장, 각각 512²다. T-013에서 water는 깊은 강바닥으로 교체하고 ford를 추가했으며 최신 규격은 아래 T-013 절을 따른다. 고정 시드 주기적 격자 노이즈를 4·8·16·32 스케일로 혼합한 방향성 없는 저대비 색 변화를 사용하며 반대편 가장자리 RGB 오차 0을 검사한다. 텍스처는 불투명 표면 컬러이며 수면 굴절이나 물리적 투명도를 포함하지 않는다. 눈은 스타일 팔레트 참고 항목이며 현 지형 ID에 없어 납품하지 않았다.

소품은 `broadleaf.glb`, `conifer.glb`, `boulder.glb` 3종이다. 활엽수는 겹친 다면체 수관 3덩어리, 침엽수는 층진 다면체, 바위는 크기·방향이 다른 절리 덩어리 2개로 차이를 준다. 버텍스 컬러 기반이며 인스턴싱용 단일 메시다.

### 검증 결과와 남은 문제

`validate.py`는 GLB 버퍼의 삼각형·정점·인덱스·정규화 웨이트·조인트 범위·inverse bind 개수·유한 좌표·공유 골격·머티리얼 구조를 검사한다. Blender 재수입 검사에서는 4종 모두 팔 관절 회전으로 정점이 실제 이동함을 확인한다. 표면 텍스처 반대쪽 가장자리와 팔레트 크기·마스크를 별도로 검사한다.

모든 형상·텍스처는 프로젝트용 코드로 직접 제작했다. 외부 에셋·레퍼런스 리소스를 사용하지 않았으며 별도 제3자 에셋 라이선스는 없다.

### 다리 배치 계약

로컬 +Y 위, +Z 길이 방향. **통행면은 Y=0**, X=-5~5m, Z=-20~20m로 10×40m다. 40장의 판재 상면이 틈 없이 이어지고 경사·돌출·계단이 없다. 원점은 통행면의 중심으로, 모델 바닥/바운딩 박스 최저점과 다르다. 모델에 월드 높이·회전·스케일을 굽지 않았다. 교각은 로컬 Y=-6m까지 내려가며 기본 배치 높이 10m에서는 GDD 강바닥 4m에 닿는다. 지형이 달라지면 A가 교각 침투·접지 상태를 검토한다.

난간 안쪽 X=±5.23m, 외측 지지대 포함 바운딩 폭은 11.2m다. 이 폭은 장식 외곽선이고 시뮬레이션 통행 폭은 10m다. 전체 GLB bounds는 X ±5.6, Y -6~1.225, Z ±20m다. 양 끝은 열려 있다.

A는 다리 칸을 둑 높이(기본 10m)로 평평하게 만들고 그 높이에 모델 원점을 놓으며, 방향은 맵 데이터에서 Y축 회전으로 적용한다. 다리 아래의 높이맵 상면을 그대로 겹쳐 렌더하면 판재 상면과 Z-fighting이 날 수 있다. 갱신된 ARCHITECTURE §7.6은 bridge 칸 렌더 정점을 강바닥 높이로 내리는 방식을 정했다. A는 시뮬레이션 높이를 둑 높이로 유지하고 이 렌더 분리를 적용한다. 요청 표의 상면 제외·polygon offset은 문서 갱신 전에 전달한 대안이며, 현재는 아키텍처의 강바닥 렌더 규칙을 따른다. 시뮬레이션 높이나 모델 통행면을 임의로 올려 해결하지 않는다.

## Base Color sRGB 저장 오류 수정 (2026-10-23)

지형 4장과 유닛 내장 팔레트는 생성기에서 sRGB 색을 Linear로 바꾼 뒤 그 값을 PNG 바이트로 저장하는 오류가 있었다. Base Color를 sRGB로 읽는 렌더러에서 중복 선형화되어 어두워졌다. 지형 4장을 sRGB로 인코딩하고, 유닛 4종은 GLB 내부 PNG만 교체했다. 모델 재생성과 애니메이션 재내보내기는 하지 않았다. 노드/골격/바인드 변환/메시/인덱스/UV/노멀/웨이트/조인트/재질 정의를 이미지 제외 해시로 비교해 동일함을 확인했다. 별도 animations.glb도 수정 전후 SHA-256이 동일하다.

팔레트 6칸 수정 전→후: 팀 #939393→#C8C8C8, 암부 #05080C→#28323D, 피부 #CAB78D→#E6DCC4, 금속 #3E4E55→#87969C, 목재 #21140F→#655044, 말 털 #6C3416→#AE7D53. 알파 마스크는 그대로다. ford·water는 이미 sRGB로 저장되어 있어 변경하지 않았다.

소품 broadleaf/conifer/boulder/bridge는 텍스처가 없으며 COLOR_0가 규격대로 **Linear**다. 실제 accessor 값이 가이드 sRGB를 한 번 선형화한 값과 일치하는 것을 검사했다. 여기에 sRGB 인코딩을 적용하면 반대 오류가 생기므로 변경하지 않았다.

수정 파일: 4장 terrain PNG, units/4종 원본 GLB의 내장 이미지, tools/art/unit_palette.png, army_source.blend의 패킹된 팔레트, generate.py, validate.py, verify_blender.py, color_io.py, fix_srgb.py, refresh_color_previews.py 및 색 검사 JSON/렌더 미리보기. fix_srgb.py는 일회성 이관용이며 평상시 생성 명령이 아니다. 원본 생성기는 이제 PNG용 sRGB와 COLOR_0용 Linear를 분리한다.

검증: `python3 tools/art/validate.py`는 4종 지형 평균색이 가이드 채널당 오차 4 이내인지 검사한다(실측 최대 0.436). 원래 오류를 재현한 Linear 저장 PNG가 같은 검사에 거부되는 음성 검사도 통과했다. 유닛 내장·원본 팔레트는 6칸 모든 픽셀의 RGB·알파를 검사한다. 소품은 Linear COLOR_0를 검사한다. 상세 측정·보존 해시는 `tools/art/srgb_correction.json`, 현재 색 검사는 `color_validation.json`에 있다. PNG 경계·GLB 재수입·스킨 변형 검사는 verify_blender.py로 재검증한다.

D-012 반영: 월드 **+X=서, +Z=북**이다. 색 수정에는 좌표·맵 데이터·모델 축 변경이 없다. 미리보기와 실제 게임 통합에서 고저 가독성 판정은 조명·노출 설정도 함께 확인한다.


## T-014 / D-015 장비의 해부학적 좌우 수정

**중요: 현 골격의 `_l` / `_r` 접미사는 해부학적 좌우와 반대다.** 정면은 +Z이며 캐릭터의 오른쪽은 -X, 왼쪽은 +X다. legacy 골격에서 `hand_l`(-X)은 해부학적 오른손, `hand_r`(+X)은 해부학적 왼손이다. 팔·다리 접미사도 같은 legacy 규칙이다. 본 이름·계층·바인드 변환은 animations.glb 호환성을 위해 그대로 유지한다. D-012의 월드 방위(+X=서)와 캐릭터 자신의 좌우를 구분한다.

| 장비 | 수정 전 위치·본 | 수정 후 위치·본 |
|---|---|---|
| 보병 검 | +X, hand_r (해부학적 왼손) | -X, hand_l (오른손) |
| 보병 방패 | -X, hand_l (오른손) | +X, hand_r (왼손) |
| 창병 창 | +X, hand_r | -X, hand_l |
| 창병 방패 | -X, hand_l | +X, hand_r |
| 궁수 활·시위 | -X, hand_l | +X, hand_r (왼손으로 활 유지, 오른팔은 당김) |
| 기병 창 | +X, hand_r | -X, hand_l |

원인은 손 위치와 웨이트의 불일치가 아니라, 제작 시 +Z 정면에서의 해부학적 좌우를 뒤집어 해석한 것이다. 기존 장비와 공격 클립은 서로 맞았으나 둘 다 해부학적 왼팔을 검/창 공격 팔로 썼다. D-015에 따라 아트 담당은 장비만 반사·교환하고, attack 곡선 및 최종 결합 검사는 애니메이션 담당에게 맡긴다.

원본 4종 GLB에서 장비 정점 POSITION.x와 NORMAL.x를 반사하고 해당 정점 JOINTS_0의 hand_l/hand_r를 교환했다. 반사한 장비 삼각형만 감김을 뒤집어 바깥 면을 유지한다. WEIGHTS_0 수치는 1.0 그대로이며 UV·팔레트·그 외 신체 정점·노드·골격·바인드는 변경하지 않았다. 선택 장비 정점 수는 보병120, 창병78, 궁수144, 기병48이다. 삼각형·정점·본 수는 기존과 동일하다. 생성기와 편집 원본에도 같은 수정을 반영했으며 모델 전체를 재내보내지 않았다.

- `tools/art/fix_handedness.py`: 일회성 GLB 장비 반사 및 웨이트 대상 교환. 중복 실행 방지 표식 포함.
- `tools/art/update_handedness_source.py`: army_source.blend만 동기화, GLB·애니메이션 내보내기 없음.
- `tools/art/handedness_correction.json`: 모델별 장비의 전후 X 범위 및 보존 검사 결과.
- `tools/art/preview_handedness.py`, `handedness_before_poses.json`, `handedness_after_poses.json`: 실제 GLTFLoader/AnimationMixer 샘플에서 장비 위치 전후 비교.
- `tools/art/handedness_position_comparison.png`: 각 병종의 기존 클립 attack 첫 프레임(f0) 전후. 바인드 포즈 자체가 아닌 동일 시작 프레임의 장비 위치 비교다.
- `tools/art/handedness_before.png`: 수정 전 attack 시작/타격 시점 기록. 최종 수정 공격 프레임은 애니메이션 담당이 제작·검수한다.

검사: validate.py에 장비가 올바른 위치의 손 본에 연결되고 검/창·방패·활이 위 표대로 연결되는 회귀 검사를 추가했다. 전체 리소스·sRGB 검사 및 Blender 재수입·관절 변형 검사는 통과했다. tools/anim/validate.py의 원본-애니메이션 노드·바인드 완전 일치 검사, verify.mjs의 24클립 재생·유한 좌표 검사도 통과했다.

단 기존 클립의 `verify.mjs --grounded` 검사에서는 die 동작 중 보병 hand_l -0.0466m, 창병 -0.8235m, 기병 -0.3645m의 무기 지면 관통이 있었다. 이를 성공으로 기록하지 않으며 INTERFACES 표와 디렉터 중계로 애니메이션 담당에게 전달했다. 공격 좌우 변경과 사망 접지 재보정은 해당 담당자의 작업이다. 아트 담당은 animations.glb를 쓰지 않았다. D-015에 따른 아트 범위는 완료, 전체 T-014 결합 완료 판정은 애니메이션 담당 결과를 기다린다.


## T-021 / D-016 원거리 LOD1 (2026-10-24)

원거리의 삼각형 부하를 줄이기 위한 독립 모델이며 렌더러 적용은 B가 일반 브라우저 실측 후 결정한다. LOD0와 animations.glb는 수정하지 않는다. 파일은 `public/assets/units/{unit}/{unit}_lod1.glb`다.

### 제작 규칙

- 보병의 넓은 방패·검, 창병의 긴 수직 창과 좁은 방패, 궁수의 열린 다각형 활, 기병의 수평 말 몸체·목·주둥이·네 다리·귀·꼬리를 남긴다.
- 머리는 앞뒤 능선이 있는 8삼각형 프리즘이다. 얼굴·투구/후드 구분은 기존 팔레트 UV로 한다. 몸통은 상자, 팔다리·장비는 삼각기둥/사면체 중심으로 줄였다.
- 원본 인체 높이 범위와 기병 높이·길이 범위를 유지하고 +Y 위/+Z 정면/바닥 원점 규칙을 지킨다. D-015에 따라 검·창은 -X hand_l, 방패·활은 +X hand_r다.
- 정점당 영향 본은 1개다. 원본 골격 전체 17본/기병 23본, 본 이름·노드 순서·계층·TRS·inverse bind 행렬은 그대로 보존한다. 사용하지 않는 본도 삭제하지 않아 클립·본 행렬 텍스처를 공유할 수 있다.
- 256² Base Color 팔레트 PNG는 원본 GLB 내장 바이트를 복사한다. sRGB RGB와 알파 팀 마스크, 샘플러·PBR 재질 정의가 원본과 완전히 같다. 단일 메시·프리미티브·머티리얼, OPAQUE다.
- 원본에서 보이지 않는 내부 겹침면이 많으므로 표면 삼각형 면적 합보다 실제 투영 마스크 면적을 함께 검토한다. 별도 방패 문양·추가 텍스처·모프 타깃은 넣지 않았다.

### 납품 수치

| unit | 삼각형(상한) | 정점 | 전체 본 / 사용 본 | 최대 영향 본 | bytes |
| infantry | 76 / 80 | 180 | 17 / 13 | 1 | 16,500 |
| spearman | 80 / 80 | 192 | 17 / 13 | 1 | 17,212 |
| archer | 80 / 80 | 188 | 17 / 12 | 1 | 17,008 |
| cavalry | 172 / 180 | 410 | 23 / 18 | 1 | 31,000 |

원본 대비 삼각형은 병종별 약 65.6~70.8% 감소한다. 이는 메시 수치이고 실제 GPU 프레임 개선 비율을 뜻하지 않는다. 모델 압축은 쓰지 않는다.

### 생성·검증·미리보기

```sh
python3 tools/art/generate_lod1.py
python3 tools/art/validate.py
python3 tools/art/validate_lod1.py
node tools/art/verify_lod1.mjs --grounded
blender --background --factory-startup --python tools/art/preview_lod1.py
blender --background --factory-startup --python tools/art/measure_lod1_mask.py
```

- generate_lod1.py: 현재 LOD0를 읽어 골격·바인드·팔레트를 복사하고 새 geometry buffer만 만든다. 출력은 *_lod1.glb와 생성 보고서뿐이다. 재생성은 결정적이며 난수가 없다.
- validate.py: LOD 전용 80/180삼각형 예산, 정점·본·파일 크기, 메시·재질 수, 손 위치/웨이트, 팔레트 sRGB를 검사한다.
- validate_lod1.py: LOD0와 노드·씬·본 순서·바인드 행렬·팔레트 PNG·재질·샘플러가 같은지, animations.glb 노드와 일치하는지 직접 검사한다. LOD0 SHA-256도 대조한다.
- verify_lod1.mjs: tools/anim/verify.mjs의 LOD1 전용 실행기. 실제 GLTFLoader와 AnimationMixer에 기존 animations.glb의 6클립을 연결해 30fps로 모든 정점을 CPU 스키닝한다. 클립 바인딩, 유한 좌표, 실제 변형, 취소 시 바인드 복원, root 채널 없음 및 바닥 관통을 검사한다. 보고서는 tools/art/에 저장하며 tools/anim/와 원본 모델·클립을 쓰지 않는다.
- preview_lod1.py: 실제 납품 GLB를 재수입해 LOD0/LOD1을 나란히 그린다. 1920×1080, 세로 FOV50°, 내려다보기50°, 주시점까지 실제 거리150/300m. 각 쌍은 왼쪽0/오른쪽1, 앞 청람/뒤 황토다. 그림을 확대해 원거리처럼 주장하지 않는다. 35m 근접 비교는 별도다.
- measure_lod1_mask.py: 같은 150m 배치에서 팀 마스크만 백색 emission으로 렌더하고 중립 부위는 검정으로 유지한다. sRGB를 선형화한 RGB 합에 알파 커버리지를 곱한 픽셀 합을 비교한다. 쌍의 위치가 다르므로 시야각·픽셀 위상 차이가 포함된 비교이며 모든 자세/방향의 보장을 뜻하지 않는다.

주요 결과 파일: `lod1_generation.json`, `lod1_validation.json`, `lod1_roundtrip.json`, `lod1_poses.json`, `lod1_preview_measurements.json`, `lod1_mask_validation.json`. `roundtrip_validation.json`에는 Blender 재수입·관절 변형 결과도 들어 있다.

미리보기: `tools/art/lod1_150m.png`, `lod1_150m_gray.png`, `lod1_300m.png`, `lod1_300m_gray.png`, `lod1_closeup.png`. 투영 높이(무기 포함)는 preview_measurements에 기록한다. 기병·창은 보행 인체 키보다 높게 보인다.
